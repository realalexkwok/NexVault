| 1.6-1 | **Critical** | `WalletRepositoryImpl.kt:66,127,183,284,332` + `WalletStore` signatures | The mnemonic's and private key's encryption "password" is the **wallet UUID** (`UUID.randomUUID()`), which is stored **in plaintext** in the `wallet_metadata` DataStore. `doubleEncrypt` derives its inner key via PBKDF2 from that public value and stores the salt next to the ciphertext, so the inner layer holds **zero secret** — the user's PIN protects nothing about the mnemonic. Additionally, `getMnemonicForBackup`/retrieval has **no auth gate** — only a comment ("Caller must ensure authentication has been performed"). Mitigation that keeps this from being a trivial remote leak: the outer AES-GCM layer is KeyStore-wrapped. The design intent (user-secret inner layer) is void; fix belongs to the 2.0.2b remediation (encrypt with the PIN once set, or drop the inner layer; and enforce authentication before retrieval). | reads 2026-09-23: `storeMnemonic(mnemonic, walletId)` at `:66`/`:127`; `retrieveMnemonic(walletId)` at `:284`/`:332`; walletId persisted via `walletMetadataStore.addWallet`; `WalletStore.storeMnemonic(mnemonic, password)` param name | **2.0.2b** — **owner decision 2026-09-23: defer to 2.0.2b** (not fixed in this round; 2.0.2b's planning must re-read this row) | **Open** |
