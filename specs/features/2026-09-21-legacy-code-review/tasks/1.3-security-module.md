| 1.3-1 | **Medium** | `SecurityUtils.kt:152–155` (`sha3Keccak`), used by `checksumAddress` (`SecurityUtils.kt:84`) | `checksumAddress` hashes with NIST **SHA3-256** (`MessageDigest.getInstance("SHA3-256")`), but Ethereum EIP-55 checksums require **Keccak-256** — a different function (different padding). Every produced checksum is wrong by construction. No production caller today (only `SecurityUtilsTest.kt:88–100`), so no live fund risk, but it is a landmine for any future share/copy flow; additionally `SHA3-256` may be unavailable below API 28 (minSdk 26). Fix: delegate to web3j `Hash.sha3` (true Keccak-256) or delete the function. | `SecurityUtils.kt:152–155`; test `testChecksumAddress` asserts only `startsWith("0x")` + length 42, so the suite cannot catch the algorithm error (2026-09-21) | **4.12** (SecurityUtils API cleanup) | **Open** |
